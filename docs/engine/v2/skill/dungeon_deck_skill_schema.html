Schema de Skills — Dungeon Deck

Modelo declarativo inspirado no skilldata.txt do Lineage 2, adaptado para o card game

1. Visão geral

Cada skill é declarada em YAML e referenciada por skillId nas cartas. A skill descreve quem afeta, quando pode ser usada, quanto custa e o que faz em cada nível de despertar. Nenhuma lógica imperativa fica embutida: todo comportamento é composição de primitivas (effects[]).

O modelo segue o princípio do L2: campos pequenos e ortogonais que se combinam, em vez de strings monolíticas que misturam várias dimensões.

2. Skill completa — exemplo de referência

id: skill_last_light_healing
name: { pt: Cura da Última Luz, en: Last Light Healing }
operate_type: op_active
nature: [nat_magical, nat_holy]

targeting:
  target_type: tgt_target
  affect_scope: scp_single
  affect_object: obj_friend
  affect_limit: { min: 1, max: 1 }

conditions:
  - { kind: awakening, gte: orange }

cost:
  mp: 2

cooldown:
  scope: combat
  charges: 1

levels:
  - awakening: white
    effects:
      - kind: i_heal
        to: $target
        amount: 3
  - awakening: orange
    effects:
      - kind: i_heal
        to: $target
        amount: 5
  - awakening: purple
    effects:
      - kind: i_heal
        to: $target
        amount: 8

3. Campos do schema

Identificação

CampoObrigatórioDescrição
idsimIdentificador único da skill, com prefixo por origem (skill_, power_, item_, etc).
namesimNome com i18n: { pt, en, ... }.

operate_type — como a skill executa

ValorSignificado
op_activeAtiva instantânea (player ativa, resolve uma vez).
op_active_buffAtiva com duração (player ativa, efeito persiste).
op_triggeredReage a evento; exige trigger.
op_passivePassiva permanente (enquanto a fonte estiver em jogo).
O campo trigger só aparece quando operate_type: op_triggered. Para os outros tipos, "quando" está implícito.

nature — natureza da skill array

Lista de categorias que a skill carrega. Cumulativa: uma skill pode ser magical e holy ao mesmo tempo, e cruzar com as resistências da criatura em ambos os eixos.

GrupoValores
Tiponat_physical · nat_magical
Elementosnat_fire · nat_water · nat_earth · nat_wind · nat_holy · nat_dark
Estadosnat_bleed · nat_poison · nat_shock · nat_paralyze · nat_sleep · nat_hold · nat_derangement
Especiaisnat_death · nat_true

Exemplos: [magical, holy] (cura sagrada), [physical, bleed] (corte profundo), [true] (ignora resistência), [] (utility sem natureza).

4. Targeting

Quatro eixos ortogonais determinam quem é atingido pela skill.

target_type — quem você seleciona

ValorSignificado
tgt_selfA própria carta.
tgt_targetAlvo escolhido (aliado ou inimigo).
tgt_enemyInimigo.
tgt_itemItem / artefato / carta de deck.
tgt_othersTodos exceto a própria carta.
tgt_noneSem alvo (auto-resolve).

affect_scope — o que o efeito atinge a partir do alvo

ValorSignificado
scp_singleSó o alvo selecionado.
scp_party_fullToda a party.
scp_dead_partyHeróis mortos da party (revive em grupo).
scp_roomOcupantes da sala atual (refinado por affect_object).
scp_noneSem área.

affect_object — filtro de aliados/inimigos

ValorSignificado
obj_friendSó aliados (da perspectiva do caster).
obj_not_friendSó inimigos.
obj_allTodos, sem filtro.
A dungeon castando affect_scope: scp_room, affect_object: obj_friend atinge os monstros (aliados dela). Um herói com a mesma config atinge sua party. O motor resolve "amigo/inimigo" pela perspectiva de quem casta.

affect_limit — quantidade

FormaSignificado
{ min: 1, max: 1 }Single target.
{ min: 1, max: 3 }"Até 3 alvos".
{ min: 2, max: 2 }Exatamente 2.
{ min: 0, max: 0 } ou omitidoSem limite (atinge todo o scope).

5. Condições, custo e cooldown

conditions — pré-requisitos para usar

Lista de condições combinadas com AND. Para OR, agrupa com any_of.

conditions:
  - { kind: awakening, gte: orange }
  - { kind: in_combat }
  - { kind: owner_hp_pct, lte: 50 }
  - any_of:
      - { kind: target_has_status, status: bleeding }
      - { kind: target_has_status, status: poisoned }
kindSignificado
awakeningDespertar atual (gte/lte/eq).
in_combatEstá em combate.
not_in_combatFora de combate.
owner_hp_pctHP% do dono da skill.
target_hp_pctHP% do alvo.
has_itemDono tem item específico.
owner_has_statusDono tem status específico.
target_has_statusAlvo tem status específico.
is_boss_roomSala atual é sala de boss.
Cor da sala é a fonte da verdade da progressão. A escala é white → yellow → orange → red → purple (5 níveis). Comparações usam ordenação dessa escala: gte: orange cobre orange, red e purple.

cost — custos para ativar

cost:
  hp: 0
  mp: 2
  discard: 0

Campos com valor 0 podem ser omitidos. Outras moedas podem ser adicionadas ao catálogo conforme o jogo evoluir.

cooldown — limite de uso

cooldown:
  scope: combat
  charges: 1
scopeReseta quando
gameNunca (uma vez por partida).
roomA cada sala nova (incluindo a do boss).
combatA cada combate.
roundA cada round.

Cooldown ausente = sem limite de uso.

6. Levels — progressão por despertar

Cada bloco em levels[] é um estágio completo da skill em um nível de despertar específico. Despertares omitidos herdam o anterior declarado. Se nenhum bloco cobre o despertar atual, a skill não dispara nesse estado — substitui o antigo requiresAwakening.

levels:
  - awakening: white
    effects:
      - { kind: i_heal, to: $target, amount: 3 }
  - awakening: orange
    effects:
      - { kind: i_heal, to: $target, amount: 5 }
  - awakening: purple
    effects:
      - kind: i_heal
        to: $target
        amount: 8
      - kind: i_dispel
        to: $target
        category: poison

Em white e yellow → cura 3. Em orange e red → cura 5. Em purple → cura 8 + dispel veneno. A skill pode ganhar qualidade nova no topo, não só escalar números.

Para skills que não escalam por despertar, o array levels contém um único bloco com awakening: white.

7. Prefixos de campo

Todo valor de catálogo carrega um prefixo curto que indica de qual eixo ele vem. Inspirado no skilldata.txt do Lineage 2 (que usa i_/p_/c_/t_), mas estendido para todos os campos. Vantagem: você nunca confunde de qual catálogo um valor é, e grep sobre um prefixo lista o uso de todo o catálogo correspondente.

Tabela consolidada

PrefixoUsado emExemplos
op_operate_typeop_active, op_passive, op_triggered
nat_nature[]nat_magical, nat_holy, nat_fire
tgt_target_typetgt_self, tgt_enemy
scp_affect_scopescp_single, scp_room
obj_affect_objectobj_friend, obj_not_friend
evt_trigger.eventevt_damage_taken, evt_room_enter
i_kind (effect instantâneo)i_damage, i_heal
p_kind (effect persistente)p_modifier, p_status
t_kind (tick no alvo)t_damage, t_heal
c_kind (tick no caster)c_damage, c_resource
s_stat em p_modifiers_damage, s_hit_bonus

Prefixos de kind — quando e onde

PrefixoQuando disparaOnde aplica
i_Instantâneo — uma vez quando a skill resolve.Lista de alvos.
p_Persistente — ativo enquanto o status/buff durar.Modifica stats do alvo.
c_Tick no caster — round/turn periódico.Sempre no próprio dono.
t_Tick no alvo — DoT / HoT periódico.Sempre no alvo.

Stats modificáveis (s_)

Stats que entidades carregam e que p_modifier pode alterar. Cada stat exige suporte no motor: campo na entidade, leitura nas fórmulas e suporte a modifier. Stats fantasmas (declarados no YAML mas não lidos pelo motor) são silenciosamente inúteis.

StatSignificado
s_damageDano base do ataque.
s_hit_bonusBônus de acerto.
s_life_maxVida máxima.
s_damage_reductionReduz dano sofrido (valor plano).
s_damage_takenMultiplicador de dano sofrido (%).
s_damage_dealtMultiplicador de dano causado (%).
s_dice_bonusModificador de dado rolado.
Catálogo inicial enxuto: começar pelo que as skills atuais usam, expandir só quando aparecer necessidade real. Cada stat novo é um contrato entre conteúdo e motor.

8. Catálogo de primitivas de efeito

Toda skill compõe seu comportamento a partir das primitivas abaixo. Adicionar uma primitiva nova exige tocar o motor; usar as existentes não exige nada além do YAML.

Dano e cura

kindFunção
i_damageDano direto.
i_healCura.
i_lifestealDreno (causa dano e cura o caster).
t_damageDoT — dano periódico no alvo (queima, veneno, sangramento).
t_healHoT — cura periódica no alvo (regen).
c_damageDreno de HP no caster por turno (custo de toggle).
c_resourceDreno de MP/recurso no caster por turno.

Modificadores e status

kindFunção
p_modifierModifica stat com operation e duration.
p_statusAplica status persistente (stunned, blessed, marked).
i_remove_modifierRemove modifier específico.
i_remove_statusRemove status específico.
i_dispelRemove categoria de status (todos os debuffs, todos os DoTs, etc).

Controle de fluxo

kindFunção
i_block_actionImpede ação.
i_prevent_next_damageAnula o próximo dano.
i_prevent_dungeon_discardEvita descarte da dungeon.
i_ignore_next_targetingIgnora o próximo targeting.
i_mark_targetMarca alvo para interação futura.

Escolha e condicionais

kindFunção
i_choose_onePlayer escolhe entre opções.
i_ifCondicional declarativo.
i_for_eachItera sobre coleção.

Dado / RNG

kindFunção
i_modify_dieAltera resultado de dado já rolado.
i_rerollRe-rola dado(s).
i_set_dieDefine valor de dado.

Dungeon / deck

kindFunção
i_reveal_dungeonRevela cartas.
i_drawCompra carta.
i_draw_and_chooseCompra e escolhe.
i_discardDescarta carta.
i_recover_dungeonRecupera carta da dungeon.
i_advance_dungeonAvança progressão.
i_set_no_rewardModifica recompensa.

Posicionamento

kindFunção
i_move_toMove carta entre zonas.
i_summonInvoca carta.

Meta

kindFunção
i_noopPlaceholder, não faz nada.

9. Referências simbólicas dentro dos effects

SímboloResolve para
$selfA entidade que está executando a skill.
$targetAlvo primário selecionado.
$eachCada elemento do scope (quando affect_scope não é scp_single).
$valueValor declarado no level atual (em vez de número fixo).
$awakeningNível atual de despertar.
effects:
  - kind: i_damage
    to: $each
    amount: { expr: "$value + $awakening" }

Expressões aritméticas usam { expr: "..." } com referências simbólicas.

10. Catálogo de eventos (trigger.event)

Eventos que skills op_triggered podem escutar. O prefixo evt_ mantém a consistência com os outros catálogos. Combinado com conditions e cooldown, cobre todos os disparos reativos que o jogo precisa.

Combate

EventoQuando dispara
evt_attack_declaredAntes de rolar ataque.
evt_rollApós rolar dado(s).
evt_hitAcerto confirmado.
evt_damage_dealtCausou dano.
evt_damage_takenSofreu dano.
evt_destroyAlgo foi destruído.
evt_killMatou algo.

Ciclo

EventoQuando dispara
evt_combat_startInício de combate.
evt_combat_endFim de combate.
evt_round_startInício de round.
evt_round_endFim de round.

Sala / dungeon

EventoQuando dispara
evt_room_revealSala revelada.
evt_room_enterEntrou na sala.
evt_room_leaveSaiu da sala.
evt_dungeon_discardCarta descartada da dungeon.

Carta / entidade

EventoQuando dispara
evt_enter_playCarta entrou em jogo.
evt_leave_playCarta saiu (destruída, descartada, fugida).
evt_targetedFoi alvo de efeito.

Exemplos de migração

O antigo once_per_room_after_roll:

operate_type: op_triggered
trigger:
  event: evt_roll
cooldown:
  scope: room
  charges: 1

O antigo combat_if_dungeon_red_or_purple:

operate_type: op_triggered
trigger:
  event: evt_combat_start
conditions:
  - { kind: awakening, gte: red }

Note como condição e cooldown deixam de ser parte do nome do trigger — são campos próprios. Os 64 triggers compostos do skills.json original colapsam para combinações de 18 eventos atômicos.
